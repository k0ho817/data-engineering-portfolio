ImageNet 데이터에서
분산 학습 worker까지

원본 이미지와 라벨 정보를 Parquet로 통합하고 Ray Data의 전처리 결과를 Ray Train worker에 공급했습니다. 저장 장치부터 GPU까지 이어지는 처리율을 한 흐름으로 확인한 프로젝트입니다.

NFSRay DataParquetRay TrainKubernetes

왜 이 구조를 선택했나

NFS

여러 GPU 노드에서 같은 ImageNet 원본과 결과를 읽어야 했습니다. 당시 환경에서 가장 빠르게 공유 저장소를 구성할 수 있는 NFS를 선택했습니다.

Parquet

이미지 바이트, 정답 라벨, 원본 경로와 WNID를 한 행에 저장했습니다. PyTorch와 TensorFlow 실험이 같은 전처리 결과를 읽도록 입력을 통일했습니다.

데이터 흐름

ParquetNFS 공유 입력
Ray Datadecode · batch
Ray TrainDDP · FSDP

처리 과정에서 확인한 문제

완료 집계
전처리 프로세스가 끝났더라도 모든 shard가 정상인지 알 수 없었습니다. 파일 존재 여부와 함께 행 수와 완료 상태를 확인하도록 점검 항목을 늘렸습니다.
shard 편차
Parquet shard마다 행 수가 달랐고 worker별 batch 수도 달라졌습니다. 파티션과 worker 단위의 처리량을 따로 기록했습니다.
CPU 비용
PNG 디코딩이 학습 중 CPU에서 반복됐습니다. GPU 사용률만 보지 않고 데이터 대기와 디코딩 구간을 함께 확인했습니다.
공급 균형
NFS 공급보다 전처리가 빠르면 worker가 입력을 기다렸고, 학습이 느릴 때는 선읽기 데이터가 캐시에 쌓였습니다. shard 내부 제한과 캐시 사용량을 조정했습니다.
