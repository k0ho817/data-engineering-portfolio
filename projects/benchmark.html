분산학습 벤치마크

같은 이름의 GPU를 사용해도 노드별 환경과 네트워크 조건은 달랐습니다. GPU 배치, 소프트웨어 환경과 완료 기준을 맞춘 뒤 실행 시간과 메모리를 기록했습니다.

공정한 비교를 위한 기준

환경 통일

NVIDIA driver와 Docker 이미지를 맞추고 PyTorch, CUDA runtime과 라이브러리 버전을 기록했습니다. 호스트 OS 차이는 실험 조건에 남겼습니다.

대칭 GPU 배치

gpu08 2개와 gpu09 2개를 사용하는 2+2 구성을 주 실험으로 정했습니다. 노드당 GPU 수가 다른 2+4 결과는 별도 운영 사례로 분리했습니다.

완료 기준

RUN_END와 결과 파일이 남은 성공 실행만 집계했습니다. TensorFlow MWMS처럼 완료 산출물이 없는 실행은 정량 비교에서 제외했습니다.

같이 기록한 지표

외부 wall-time, step time, 데이터 대기, PyTorch allocated·reserved와 GPU UUID 기반 NVML 메모리를 저장했습니다.

관측에서 수정까지

GPU 종료
부하가 높을 때 노드가 종료되는 패턴을 확인하기 위해 nvidia-smi 값을 계속 기록했습니다. 여러 GPU의 동시 전력 사용을 확인한 뒤 power limit을 적용하고 실험 제약에 적었습니다.
NVML index
Ray가 CUDA_VISIBLE_DEVICES를 다시 매핑해 논리 GPU 번호와 NVML 번호가 달라졌습니다. GPU UUID로 장치를 찾아 메모리를 기록하도록 수정했습니다.
선읽기
진단 실행에서 27.1k행·3.5GiB를 읽었습니다. shard 내부 제한을 적용한 실행에서는 12행·약 61KiB로 줄어 입력 범위를 통제했습니다.
비교 제외
TensorFlow MWMS 실행은 collective worker failure 뒤 완료 파일을 만들지 못했습니다. DDP·FSDP와 같은 기준의 지표가 없어 결과 표에서 제외했습니다.

이 실험에서 배운 기준

빠른 결과보다 비교 가능한 결과를 남겼습니다.하드웨어 배치와 완료 기준이 다르면 프레임워크 차이로 해석하지 않았습니다. 실패 로그도 덮어쓰지 않고 원인별로 분류해 다음 실행 조건을 정하는 데 사용했습니다.
