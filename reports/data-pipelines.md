# DBLAB 데이터 처리 구현 기록

DBLAB에서 다룬 연구용 코드·문서·메타데이터를 기준으로 처리 흐름을 정리했다. 공개 저장소에는 설명과 결과 요약을 담고, 연구실 내부 설정과 원천 데이터는 제외했다.

## FineWeb 입력 표준화

`download_fineweb_subset.py`는 스트리밍 입력을 선별하여 Parquet에 저장한다. `tokenize_fineweb_subset.py`는 토큰화·EOS·고정 길이 packing을 수행하고 처리량과 남은 토큰을 기록한다.

공유 저장소의 2026-08 메타데이터:

| 항목 | 기록 값 |
| --- | ---: |
| 수집 문서 | 50,000 |
| 생성 시퀀스 | 104,683 |
| 시퀀스 길이 | 512 |
| 출력에서 제외된 잔여 토큰 | 152 |

표의 수치는 2026년 8월 실행 시 저장된 메타데이터에서 가져왔다.

## Spark ImageNet 전처리

`spark/preprocessing.py`의 구현 흐름:

1. binaryFile로 JPEG와 파일 메타데이터 읽기.
2. 경로·파일명에서 synset 추출.
3. distinct·정렬·row_number로 라벨 맵 생성.
4. broadcast join으로 라벨을 결합.
5. 파티셔닝·파티션 내부 정렬·ZSTD Parquet 출력.
6. 이미지 수·라벨 수·바이트 수 요약 작성.

전처리는 PySpark DataFrame API로 작성했다. `512`는 라벨 기준 재분배에 사용한 파티션 설정값이다.

## 센서 데이터

`logToCSV.py`에서 센서 로그를 구조화했고, `trans.ipynb`에서 시간 파싱·ROI 분리·프레임 매핑·클래스 변환을 수행했다. 공개 그림에는 원본 로그에서 추출한 좌표 표본을 사용했다.

## 벡터 데이터

Milvus 노트북에서 컬렉션 스키마를 정의하고 임베딩을 배치 적재한 뒤 여러 색인으로 같은 질의를 실행했다. 다음 단계는 반복 질의와 Recall@k를 추가해 검색 속도와 품질을 함께 비교하는 것이다.
