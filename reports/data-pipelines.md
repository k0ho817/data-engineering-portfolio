# DBLAB 데이터 처리 구현 기록

2026-09-21 연구용 코드·문서·메타데이터 확인 기준. 연구실 공동 자료를 토대로 처리 흐름을 정리했으며 개인별 기여율이나 단독 구축 성과를 의미하지 않는다. 내부 서버 주소, 원천 데이터, 인증 설정은 공개하지 않는다.

## FineWeb 입력 표준화

`download_fineweb_subset.py`는 스트리밍 입력을 선별하여 Parquet에 저장한다. `tokenize_fineweb_subset.py`는 토큰화·EOS·고정 길이 packing을 수행하고 처리량과 남은 토큰을 기록한다.

공유 저장소의 2026-08 메타데이터:

| 항목 | 기록 값 |
| --- | ---: |
| 수집 문서 | 50,000 |
| 생성 시퀀스 | 104,683 |
| 시퀀스 길이 | 512 |
| 출력에서 제외된 잔여 토큰 | 152 |

파일에 저장된 기록이며 이번에 원천 데이터를 다시 수집하거나 Parquet를 전수 집계한 값은 아니다. 동일 코드의 노드별 사본을 별도 프로젝트로 계산하지 않는다.

## Spark ImageNet 전처리

`spark/preprocessing.py`의 구현 흐름:

1. binaryFile로 JPEG와 파일 메타데이터 읽기.
2. 경로·파일명에서 synset 추출.
3. distinct·정렬·row_number로 라벨 맵 생성.
4. broadcast join으로 라벨을 결합.
5. 파티셔닝·파티션 내부 정렬·ZSTD Parquet 출력.
6. 이미지 수·라벨 수·바이트 수 요약 작성.

이는 SQL 문자열이 아닌 PySpark DataFrame API다. 512개 파티션은 코드 설정값이며 실제 생성 파일 수가 아니다. 해당 Spark 작업의 완료 수치와 Spark 대비 Ray의 속도 개선은 검증되지 않아 기재하지 않는다.

## 센서 데이터

`logToCSV.py`의 로그 구조화와 `trans.ipynb`의 시간 파싱·ROI 분리·프레임 매핑·클래스 변환을 확인했다. 서로 다른 작업 자료이며 하나의 상용 자동 파이프라인으로 통합되었다고 주장하지 않는다. 공개 그림은 기존에 추출한 원본 좌표 표본을 사용한다.

## 벡터 데이터

Milvus 노트북에서 컬렉션 스키마, 배치 적재, 색인 생성과 검색 코드 및 저장된 검색 결과를 확인했다. 단일 질의 시간만으로 Recall@k·반복 지연시간·운영 성능을 주장하지 않는다. Faiss/Milvus는 관계형 SQL과 별도의 기술 경험이다.
